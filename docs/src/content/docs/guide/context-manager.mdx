The agent sends its whole history to the model on every call, so a long run sends more with each step: every tool call adds its result, a file read, a page fetched or a command's output. The context manager keeps it down in two ways: it replaces old tool results with a placeholder once the model's input grows past a limit, and it replaces old screenshots once the history holds too many.

## Turning it on

Without a context manager, an agent acts as with one whose settings are all left out: the image cap is on at its defaults, and the token limit is off until you give `max_input_tokens`. Either at `0` is off. Every setting has a default:

| Setting | Default | What it is |
| --- | --- | --- |
| `max_input_tokens` (`maxInputTokens`) | 0 | The input the model reports, in tokens, past which old tool results are replaced. `0` turns truncation off. |
| `preserve_recent_turns` (`preserveRecentTurns`) | 3 | How many of the latest user turns are left as they are. |
| `max_images` (`maxImages`) | 30 | Images in tool results the history may hold at the start of a turn. `0` turns the cap off. |
| `preserve_recent_images` (`preserveRecentImages`) | 10 | Images in tool results left once the cap is passed. |

`context_manager()` with no arguments (`contextManager()`, `ContextManager::default()`) is the same as setting none.

## Tool results past the token limit

Before each call to the model, the agent looks at the last input token count the model reported. When that is more than `max_input_tokens`, it truncates the history:

- A turn is a user message and everything after it up to the next user message. The last `preserve_recent_turns` turns are left as they are, and with fewer turns than that in the history nothing changes.
- In the turns before those, each tool result's contents become the text `[context truncated]`. The result keeps the id of the call it answers, since APIs such as Anthropic's refuse a tool call that has no result.
- The system message, the user's messages and the model's own messages, tool calls included, stay whole. No message is removed.

The placeholders replace the results in the agent's history, so `agent.history` shows them too, and they stay in it.

Because the count comes from a call already made, the first call that goes past the limit is sent whole, and the history is truncated before the next one. A reply without `usage` leaves the last count in place, so a model that never reports usage, such as a model of your own whose replies leave it out, never triggers it. And since only tool results are replaced, a history whose messages alone are past the limit keeps growing.

:::caution
With `preserve_recent_turns` at `0`, every tool result is replaced, those of the turn in progress too, so past the limit the model no longer sees the results of the tools it has just called.
:::

## Images past the cap

A screenshot the agent takes stays in a tool result and is sent again with every call, at about 1,500 tokens each, and a screen changes with every click. So at the start of each turn, when the tool results hold more than `max_images` images, the oldest become the text `[image from an earlier turn removed]` until `preserve_recent_images` remain. Many go at once, so the prompt cache breaks once in several turns rather than at every one.

- Only images in tool results count and only they are replaced: a screenshot, an image read with `imgread`, an image an MCP tool returned. Images you attach to a message are never touched.
- Within a turn nothing is replaced, so a turn of many screenshots sends them all until the next turn starts. Claude rejects a history altered before thinking it is handed back, and only at the start of a turn is there none.
- The cap counts across every turn, the last `preserve_recent_turns` included.

As with the token limit, the placeholders stay in `agent.history`.

Apart from the cap, and for every model, an embedded image past 2576 pixels on its longer edge, attached or returned by a tool, is shrunk to that edge before it enters the history: 2576 is the largest edge Claude takes, and Claude refuses an edge over 3000 in a request of more than twenty images. The shrunk image is turned upright by its EXIF orientation and keeps its color profile; a WebP comes back as PNG when it has transparent pixels or was lossless, and as JPEG otherwise. An animated image is left as it is, so its frames reach the model's API as they came.
