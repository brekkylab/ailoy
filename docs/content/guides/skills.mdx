:::note[Needs a sandbox]
The agent reads its skills through its sandbox, so an agent with skills needs one: `use_sandbox` in its spec, and a sandbox given to `from_spec` ([Giving an agent a sandbox](/docs/guides/sandbox/)).
:::

A skill is a folder of instructions for one kind of task, with the files those instructions use, in the [Agent Skills](https://agentskills.io/specification) format. The agent is told which skills it has and what each is for, and to read a skill's instructions when a task matches it.

## What a skill folder holds

A `SKILL.md`, and anything it refers to: scripts, references, data. `SKILL.md` opens with YAML frontmatter giving the skill's `name` and a `description` of what it does and when to use it, and the instructions follow. This is the start of the one in `examples/laya/shared`, whose instructions tell the agent to run `run_laya.py` from the same folder:

````markdown
---
name: laya
description: Answer typed questions about a text with Laya, a machine learning model for decisions. Use it to classify, score or answer yes or no about a message, an email or a ticket, with calibrated probabilities.
---

# Laya

Laya is a machine learning model for decisions. Given a text, such as a message, an email or a
ticket, it answers typed questions about it with calibrated probabilities. It picks one of
several options, rates on an ordered scale, or answers yes or no, and it generates no text.
You put what is to be decided to it as questions, and write the reply yourself from its
answers.

## Running it

Run `run_laya.py` from this directory with the mode and the request as its two arguments.

```sh
python3 run_laya.py bf16 '{"state": "...", "questions": {...}}'
```
````

Ailoy reads `name` and `description` and nothing else from the frontmatter, each as one line: keep each on a single line, without YAML's `>` or `|`.

## Giving the agent a skill

The spec's `skills` lists each skill's folder (`skill(dir)` in Rust, once for each skill), by its path in the agent's sandbox, not on your machine. Put the folder in the sandbox Ailoy makes for the agent, with whatever its instructions expect to find there: Laya's instructions read its model from `/models`, which `examples/laya` puts on a volume of its own. A volume, as below, keeps the skill on the virtx server between runs, and the `sandbox` given to `from_spec` mounts it. Baking it into the image works too ([Mounting volumes](https://virtx.sh/docs/guides/mounting-volumes/), [Images](https://virtx.sh/docs/guides/images/)).

When the agent writes the system message itself, its first turn reads the frontmatter of each `SKILL.md` through the sandbox before the model is called, and fails if the `SKILL.md` of a folder in `skills` is missing or has no `name` or `description`. The system message gets a list of the skills after the instruction: each one's name, description and location, and a line telling the model to read a skill's `SKILL.md` in full before using it. The rest of `SKILL.md` stays out of the system message; the agent reads it with its own tools. So an agent with skills needs `use_sandbox`, which brings a tool that reads files, such as `read`.

For `anthropic` models the list is an XML block:

```text
# Skills

The following skills provide specialized instructions for specific tasks. When a task matches a skill's description, read the SKILL.md at its location in full before proceeding. When a skill refers to a relative path, resolve it against the skill's directory, the one that holds its SKILL.md.

<available_skills>
  <skill>
    <name>laya</name>
    <description>Answer typed questions about a text with Laya, a machine learning model for decisions. Use it to classify, score or answer yes or no about a message, an email or a ticket, with calibrated probabilities.</description>
    <location>/skills/laya/SKILL.md</location>
  </skill>
</available_skills>
```

For any other org, the same preamble is followed by a Markdown list, one line per skill:

```text
- `laya` at /skills/laya/SKILL.md. Answer typed questions about a text with Laya, a machine learning model for decisions. Use it to classify, score or answer yes or no about a message, an email or a ticket, with calibrated probabilities.
```

Skills are added only to the system message the agent writes itself. A `history` given to `from_spec` that brings a system message keeps it: the skills are not read or added.

## Skills from the sandbox's abins

A sandbox can be made with some of virtx's own programs, its abins, at `/abin`: `index` indexes document files and searches them, `docread` reads a Word, PDF or text file a window at a time, and `display` runs GUI programs on a screen watched over VNC. Each comes with a `SKILL.md` at `/abin/skills/{name}/`, and the agent lists it among its skills without it being in `skills`. The abins go in the `sandbox` given to `from_spec`:

An abin with no `SKILL.md` is left out of the list rather than failing the turn. [Setting up sandboxes](https://virtx.sh/docs/guides/setting-sandboxes/) covers the `abins` option.

## Troubleshooting

| What you see | Why, and what to do |
| --- | --- |
| `reading the skill <dir>/SKILL.md` when the first turn starts | The `SKILL.md` of a folder in `skills` isn't in the sandbox. `dir` is a path in the sandbox, not on your machine: check that the volume holding it is mounted there. |
| ``the frontmatter has no `name` ``, or ``no `description` `` | Add the field to the frontmatter, on one line. |
| ``a SKILL.md opens with a `---` line`` | The file must start with the frontmatter, between two `---` lines. |
| `an agent with skills needs a sandbox to read them from` | Set `use_sandbox` in the spec (`sandbox()` in Rust) and give `from_spec` a `sandbox`. |
| A skill's description in the system message is just `>` or `\|` | YAML's multi-line values aren't read, and no error is raised: put the description on one line. |
