:::note[Needs a sandbox]
The agent reads its skills from its sandbox, so an agent with skills needs one ([Give an agent a sandbox](/docs/guides/sandbox/)).
:::

A skill is a folder with instructions for one kind of task, plus any files those instructions use. Skills follow the [Agent Skills](https://agentskills.io/specification) format. The agent is told which skills it has and what each is for, and reads a skill's full instructions when a task matches it.

## Write a skill

A skill folder contains a `SKILL.md` file and anything it refers to, such as scripts, reference documents or data. `SKILL.md` starts with YAML frontmatter that gives the skill's `name` and a `description` of what it does and when to use it. The instructions follow.

This is the start of the skill in [`laya/shared`](https://github.com/brekkylab/ailoy-examples/tree/main/laya/shared) in ailoy-examples. Its instructions tell the agent to run `run_laya.py` from the same folder:

````markdown
---
name: laya
description: Answer typed questions about a text with Laya, a machine learning model for decisions. Use it to classify, score or answer yes or no about a message, an email or a ticket, with calibrated probabilities.
---

# Laya

Laya is a machine learning model for decisions. Given a text, such as a message, an email or a
ticket, it answers typed questions about it with calibrated probabilities. It picks one of
several options, rates on an ordered scale, or answers yes or no, and it generates no text.
You put what is to be decided to it as questions, and write the reply yourself from its
answers.

## Running it

Run `run_laya.py` from this directory with the mode and the request as its two arguments.

```sh
python3 run_laya.py bf16 '{"state": "...", "questions": {...}}'
```
````

:::caution[Keep `name` and `description` on one line each]
Ailoy reads only `name` and `description` from the frontmatter, and each must fit on a single line. Don't use YAML's multi-line `>` or `|` syntax: Ailoy won't raise an error, but the description will be just `>` or `|`.
:::

## Give the agent a skill

1. **Put the skill folder in the sandbox.** `skill(dir)` takes a path inside the sandbox, not on your machine. A volume keeps the skill on the virtx server between runs, as in the example below. You can also build it into the image ([Mounting volumes](https://virtx.sh/docs/guides/mounting-volumes/), [Images](https://virtx.sh/docs/guides/images/)).
2. **Add anything the instructions expect.** For example, Laya's instructions read a model from `/models`, which the [laya example](https://github.com/brekkylab/ailoy-examples/tree/main/laya) puts on its own volume.
3. **Call `.skill(dir)` once for each skill.**

## What the model sees

When you call `build()`, Ailoy reads the frontmatter of each `SKILL.md` from the sandbox. The build fails if a `SKILL.md` is missing or has no `name` or `description`.

The system message lists the skills after your instruction: each skill's name, description and location, plus a line telling the model to read a skill's `SKILL.md` in full before using it. The rest of `SKILL.md` isn't in the system message. The agent reads it with its file tools when it needs it.

For `anthropic` models, the list is an XML block:

```text
# Skills

The following skills provide specialized instructions for specific tasks. When a task matches a skill's description, read the SKILL.md at its location in full before proceeding. When a skill refers to a relative path, resolve it against the skill's directory, the one that holds its SKILL.md.

<available_skills>
  <skill>
    <name>laya</name>
    <description>Answer typed questions about a text with Laya, a machine learning model for decisions. Use it to classify, score or answer yes or no about a message, an email or a ticket, with calibrated probabilities.</description>
    <location>/skills/laya/SKILL.md</location>
  </skill>
</available_skills>
```

For other orgs, the same text is followed by a Markdown list, one line per skill:

```text
- `laya` at /skills/laya/SKILL.md. Answer typed questions about a text with Laya, a machine learning model for decisions. Use it to classify, score or answer yes or no about a message, an email or a ticket, with calibrated probabilities.
```

Skills are only added when the agent writes the system message itself. If you pass a `history(...)` that already has a system message, the agent keeps it and doesn't read or add skills.

## Skills from built-in programs

virtx can add built-in programs, called abins, to a sandbox at `/abin`:

| Program | What it does |
| --- | --- |
| `index` | Indexes document files and searches them. |
| `docread` | Reads a Word, PDF or text file one section at a time. |
| `display` | Runs GUI programs on a screen you can watch over VNC. |

Each comes with a `SKILL.md` at `/abin/skills/<name>/`. The agent lists these skills automatically, without a `.skill(...)` call. Choose the programs when you create the sandbox:

<Tabs syncKey="lang">

<TabItem label="Python" icon="seti:python">

```python
sandbox = await client.create_sandbox("python:3.12-slim-trixie", abins=["index", "docread"])
```

</TabItem>
<TabItem label="Node.js" icon="seti:javascript">

```js
const sandbox = await client.createSandbox('python:3.12-slim-trixie', { abins: ['index', 'docread'] })
```

</TabItem>
<TabItem label="Rust" icon="seti:rust">

```rust
let sandbox = client
    .create_sandbox(&SandboxCreateArgs::new("python:3.12-slim-trixie").abin("index").abin("docread"))
    .await?;
```

A program without a `SKILL.md` is left out of the list instead of failing `build()`. See virtx's [Setting up sandboxes](https://virtx.sh/docs/guides/setting-sandboxes/) for the `abins` option.

## Troubleshooting

| Error | Cause and fix |
| --- | --- |
| `reading the skill <dir>/SKILL.md` at `build()` (a `VirtxError` with status `404` in Python and Node.js) | The `SKILL.md` isn't in the sandbox. `dir` is a path inside the sandbox, not on your machine: check that the volume holding the skill is mounted there. |
| ``the frontmatter has no `name` ``, or ``no `description` `` | Add the field to the frontmatter, on one line. |
| ``a SKILL.md opens with a `---` line`` | The file must start with the frontmatter, between two `---` lines. |
| `an agent with skills needs a sandbox to read them from` | Give the agent a sandbox with `sandbox(...)`. |
| A skill's description in the system message is just `>` or `\|` | Multi-line YAML values aren't supported. Put the description on one line. |
