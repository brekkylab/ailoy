An agent is a model plus what you give it, written down as its spec. `Agent.from_spec` makes an agent of a spec, with the history it starts from and what its sandbox is made of.

## The spec at a glance

In Python and Node.js a spec is a plain dict or object in its JSON form; in Rust it is an `AgentSpec`, whose calls each return it, so they chain.

| Key | Rust | What the agent gets | Where it is covered |
| --- | --- | --- | --- |
| `model` | `AgentSpec::new(model)` | The model, by name. | [Model providers](/docs/guides/model-providers/) |
| `instruction` | `instruction(text)` | The system message's text. | [Below](#instruction) |
| `use_sandbox` | `sandbox()` | A sandbox to work in, and a shell and file tools there. | [Giving an agent a sandbox](/docs/guides/sandbox/) |
| `tools` | `tool(name)`, `tools(names)` | Tools by name: your own functions, or a registered MCP server's. | [Tools](/docs/guides/tools/#your-own-functions), [Using MCP](/docs/guides/using-mcp/) |
| `tools`: `web_search`, `web_fetch` | `web_search_tool()`, `web_fetch_tool()` | Searching the web and reading a page, from your program. | [Tools](/docs/guides/tools/#the-web) |
| `use_browser` | `browser()` | The browser in its sandbox, which it drives with the `browser` tools. | [Using a browser](/docs/guides/using-browser/) |
| `skills` | `skill(dir)` | A folder of instructions in its sandbox, for one kind of task. | [Skills](/docs/guides/skills/) |
| `truncation` | `truncation(...)` | Old tool results and images cut once a run's input grows past a limit. | [Truncation](/docs/guides/truncation/) |
| `model_options` | `thinking_effort(effort)`, `output_schema(schema)` | How much the model thinks, and a JSON schema its answers must match. | [Model providers](/docs/guides/model-providers/#model-options) |

Beside the spec, `from_spec` takes the history to continue ([Running an agent](/docs/guides/running/#many-turns)) and what to make the sandbox of.

## Instruction

`instruction` is the system message's text: who the agent is, what it is for, and where in its sandbox to find inputs and leave results. The agent writes the system message from this text and the list of its [skills](/docs/guides/skills/), those of `skills` and those of its sandbox's abins, and puts that message at the front of its history, unless the history you give it already has one.

## Making an agent

A spec is plain JSON, which you can store and make an agent of again. The rest, the history and the sandbox, is given beside it:

spec = {
    "model": "anthropic/claude-haiku-5-5",

```rust
use ailoy::{
    Agent,
    agent::{AgentSpec, SessionSandbox, default_provider},
};
use serde_json::json;
use virtx::SandboxCreateArgs;

default_provider().write().unwrap().virtx = Some(client.clone());

let spec: AgentSpec = serde_json::from_value(json!({
    "model": "anthropic/claude-haiku-5-5",
    "instruction": "Answer in one sentence.",
    "use_sandbox": true,
}))?;
let sandbox = SessionSandbox::Create(SandboxCreateArgs::new("python:3.12-slim-trixie"));
let agent = Agent::from_spec(spec, saved_messages, Some(sandbox)).await?;
```

A spec says whether the agent works in a sandbox (`use_sandbox`) and drives the browser in it (`use_browser`). `from_spec` is given what to make a sandbox of exactly when `use_sandbox` is set, or it fails; with `use_browser`, the sandbox has to be made with the `browser` abin, or the agent's first turn fails. A sandbox brings the shell and file tools without the spec listing them, and a browser the `browser` and `browser_screenshot` tools. A tool the spec names itself, such as its own `shell`, is used in place of the sandbox's.

The sandbox is made on the virtx server of the client given to `set_virtx` (`setVirtx` in Node.js, the default provider's `virtx` in Rust); [Giving an agent a sandbox](/docs/guides/sandbox/) covers what it can be made of.

## Closing

`close()` lets go of the agent and its history, and removes its sandbox. It waits for a turn being iterated to finish. Read what you need from the sandbox before closing the agent. In Python, `async with agent:` closes it at the end of the block. In Rust, call `close().await` too: dropping the agent keeps it, and its sandbox, until the process ends.
