An agent is a model plus what you give it. `AgentBuilder` takes the model's name, then one call for each thing the agent should have, and `build()` makes the agent.

## AgentBuilder at a glance

Every call returns the builder, so they chain. Node.js spells them in camelCase (`webSearchTool`, `thinkingEffort`).

| Call | What the agent gets | Where it is covered |
| --- | --- | --- |
| `instruction(text)` | The system message's text. | [Below](#instruction) |
| `sandbox(sandbox)` | A virtx sandbox to work in, and a shell and file tools there. | [Giving an agent a sandbox](/docs/guides/sandbox/) |
| `tool(name)`, `tools(names)` | Tools by name: your own functions, or a registered MCP server's. | [Tools](/docs/guides/tools/#your-own-functions), [Using MCP](/docs/guides/using-mcp/) |
| `web_search_tool()`, `web_fetch_tool()` | Searching the web and reading a page, from your program. | [Tools](/docs/guides/tools/#the-web) |
| `browser()` | The browser in its sandbox, which it drives with the `browser` tools. | [Using a browser](/docs/guides/using-browser/) |
| `skill(dir)` | A folder of instructions in its sandbox, for one kind of task. | [Skills](/docs/guides/skills/) |
| `truncation(...)` | Old tool results and images cut once a run's input grows past a limit. | [Truncation](/docs/guides/truncation/) |
| `thinking_effort(effort)`, `output_schema(schema)` | How much the model thinks, and a JSON schema its answers must match. | [Model providers](/docs/guides/model-providers/#model-options) |
| `history(messages)` | An earlier conversation to continue. | [Running an agent](/docs/guides/running/#many-turns) |

## Instruction

`instruction(...)` is the system message's text: who the agent is, what it is for, and where in its sandbox to find inputs and leave results. The agent writes the system message from this text and the list of its [skills](/docs/guides/skills/), those of `skill(...)` and those of its sandbox's abins, and puts that message at the front of its history, unless the history you give it already has one.

## From a spec

The model, the instruction, the tools, the skills, the model options and whether it uses a sandbox or a browser make up an agent's spec: plain JSON, which you can store and build an agent from again. The rest (its history and its sandbox) is its state, given beside the spec. `Agent.from_spec` builds an agent from both:

```python
    "model": "anthropic/claude-haiku-5-5",
    "instruction": "Answer in one sentence.",
    "use_sandbox": True,
}
agent = await Agent.from_spec(spec, history=saved_messages, sandbox=sandbox)
```

<TabItem label="Rust" icon="seti:rust">

```rust
use ailoy::agent::{Agent, AgentSpec, AgentState};
use serde_json::json;

let spec: AgentSpec = serde_json::from_value(json!({
    "model": "anthropic/claude-haiku-5-5",
    "instruction": "Answer in one sentence.",
    "use_sandbox": true,
}))?;
let state = AgentState::new()
    .with_history(saved_messages)
    .with_sandbox(sandbox);
let agent = Agent::try_with_state(spec, state).await?;
```


</TabItem>

A spec says whether the agent works in a sandbox (`use_sandbox`) and drives the browser in it (`use_browser`); `sandbox(...)` and `browser()` on the builder set them. The state has to hold a sandbox exactly when `use_sandbox` is set, and with `use_browser` a sandbox with the `browser` abin, or building the agent fails. A sandbox brings the shell and file tools without the spec listing them, and a browser the `browser` and `browser_screenshot` tools. A tool the spec names itself, such as its own `shell`, is used in place of the sandbox's.

## Closing

In Python and Node.js, `close()` releases what the agent holds: its model and its hold on the sandbox's client. It waits for a turn being iterated to finish. In Python, `async with agent:` closes it at the end of the block. A Rust agent releases them when it is dropped.

Closing an agent leaves its sandbox as it is, for you to use again or remove.
