You create an agent with `AgentBuilder`. Pass the model's name, chain one method for each thing the agent should have, then call `build()`:

<Tabs syncKey="lang">

<TabItem label="Python" icon="seti:python">

```python
agent = await (
    AgentBuilder("anthropic/claude-haiku-5-5")
    .instruction("You are a data analyst. Write results into /artifacts.")
    .sandbox(sandbox)
    .web_fetch_tool()
    .build()
)
```

</TabItem>
<TabItem label="Node.js" icon="seti:javascript">

```js
const agent = await new AgentBuilder('anthropic/claude-haiku-5-5')
  .instruction('You are a data analyst. Write results into /artifacts.')
  .sandbox(sandbox)
  .webFetchTool()
  .build()
```

</TabItem>
<TabItem label="Rust" icon="seti:rust">

```rust
let agent = AgentBuilder::new("anthropic/claude-haiku-5-5")
    .instruction("You are a data analyst. Write results into /artifacts.")
    .sandbox(sandbox)
    .web_fetch_tool()
    .build()
    .await?;
```

</TabItem>
</Tabs>

## Builder methods

Every method returns the builder, so you can chain them. Node.js uses camelCase names (`webSearchTool`, `contextManager`). The [AgentBuilder reference](/docs/sdk/agent-builder/) lists every parameter.

| Method | What the agent gets | Guide |
| --- | --- | --- |
| `instruction(text)` | Your system prompt. | [Below](#write-the-instruction) |
| `sandbox(sandbox)` | A virtx sandbox, plus shell and file tools that run in it. | [Give an agent a sandbox](/docs/guides/sandbox/) |
| `tool(desc)`, `tools(descs)` | Your own functions, or an MCP server's tools. | [Tools](/docs/guides/tools/#add-your-own-function), [Use MCP servers](/docs/guides/using-mcp/) |
| `web_search_tool(engines)`, `web_fetch_tool()` | Web search and page fetching, run from your program. | [Tools](/docs/guides/tools/#web-search-and-fetch) |
| `browser(...)` | A web browser it controls with `browser_*` tools. | [Use a browser](/docs/guides/using-browser/) |
| `skill(dir)` | A folder of task instructions in its sandbox. | [Skills](/docs/guides/skills/) |
| `memory(dir)` | Notes about the user that last between sessions. | [Memory](/docs/guides/memory/) |
| `context_manager(...)` | Limits on how much old tool output and how many old images are kept. | [Manage context](/docs/guides/context-manager/) |
| `thinking_effort(effort)` | How much the model reasons before answering: `low`, `medium` or `high`. | [Model options](/docs/guides/model-providers/#model-options) |
| `output_schema(schema)` | A JSON schema the model's answers must match. | [Model options](/docs/guides/model-providers/#model-options) |
| `history(messages)` | An earlier conversation to continue. | [Continue a conversation](/docs/guides/running/#continue-a-conversation) |

## Write the instruction

`instruction(...)` sets the system prompt. Use it to say who the agent is, what it's for, and where in its sandbox to find inputs and save results. For example: `"Write what you are asked for into /artifacts."`

The agent builds the full system message from your instruction, the list of its [skills](/docs/guides/skills/) and the notes in its [memory](/docs/guides/memory/). If you pass a history that already has a system message, the agent uses that message instead and adds nothing to it.

## Build an agent from a spec

An agent's spec (model, instruction, tools, skills, memory and model options) is plain JSON. You can save it and build the same agent later with `Agent.from_spec` (`Agent.fromSpec` in Node.js). The agent's state, its history and sandbox, is passed alongside:

<Tabs syncKey="lang">

<TabItem label="Python" icon="seti:python">

```python
from ailoy import Agent

spec = {
    "model": "anthropic/claude-haiku-5-5",
    "instruction": "Answer in one sentence.",
}
agent = await Agent.from_spec(spec, history=saved_messages, sandbox=sandbox)
```

</TabItem>
<TabItem label="Node.js" icon="seti:javascript">

```js
const { Agent } = require('@brekkylab/ailoy')

const spec = {
  model: 'anthropic/claude-haiku-5-5',
  instruction: 'Answer in one sentence.',
}
const agent = await Agent.fromSpec(spec, { history: savedMessages, sandbox })
```

</TabItem>
<TabItem label="Rust" icon="seti:rust">

```rust
use ailoy::agent::{Agent, AgentSpec, AgentState};
use serde_json::json;

let spec: AgentSpec = serde_json::from_value(json!({
    "model": "anthropic/claude-haiku-5-5",
    "instruction": "Answer in one sentence.",
}))?;
let state = AgentState::new()
    .with_history(saved_messages)
    .with_sandbox(sandbox);
let agent = Agent::try_with_state(spec, state).await?;
```

</TabItem>
</Tabs>

:::caution[A spec must list the sandbox tools itself]
`.sandbox(...)` on the builder adds the shell and file tools to the agent. A sandbox passed to `from_spec` does not: the spec must already list those tools. In Rust, call `.sandbox_tools()` on the `AgentSpec` to add them. Python and Node.js have no equivalent, so to restore an agent that has a sandbox, use `AgentBuilder` with `.history(...)` and `.sandbox(...)` instead.
:::

## Close the agent

In Python and Node.js, call `close()` when you're done. It releases the model, any browser the agent started, and the agent's connection to the sandbox. If a turn is still running, `close()` waits for it to finish. In Python, `async with agent:` closes the agent at the end of the block. In Rust, the agent releases everything when it is dropped.

Closing the agent doesn't touch its sandbox. You can reuse the sandbox or remove it yourself.
