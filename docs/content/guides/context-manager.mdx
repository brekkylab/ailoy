An agent sends its whole history to the model on every call. In a long run, each tool result (a file it read, a page it fetched, a command's output) makes the next request bigger. The context manager keeps the history down in two ways:

- **Token limit.** Once the model's input passes a limit you set, old tool results are replaced with a short placeholder. Off by default.
- **Image cap.** Once the history holds too many images from tool results, the oldest are replaced. On by default.

## Configure the context manager

Call `context_manager(...)` (`contextManager` in Node.js) on the builder. Any setting you leave out keeps its default. An agent without this call behaves as if it had one with every default: the image cap is on and the token limit is off.

| Setting | Default | What it does |
| --- | --- | --- |
| `max_input_tokens` (`maxInputTokens`) | `0` | The input size, in tokens, above which old tool results are replaced. `0` turns this off. |
| `preserve_recent_turns` (`preserveRecentTurns`) | `3` | How many of the most recent turns are never changed. |
| `max_images` (`maxImages`) | `30` | How many tool-result images the history can hold at the start of a turn. `0` turns the cap off. |
| `preserve_recent_images` (`preserveRecentImages`) | `10` | How many tool-result images are kept once the cap is reached. |

## How the token limit works

At the start of each turn, after your message is added to the history, the agent checks the last input token count the model reported. If it's above `max_input_tokens`, the agent shortens the history:

- A turn is a user message and everything after it, up to the next user message. The last `preserve_recent_turns` turns, including the one just started, are left as they are. `1` and `0` both keep only the current turn.
- In older turns, the content of each tool result becomes `[context truncated]`. The result keeps the id of the call it answers, because some APIs, such as Anthropic's, reject a tool call without a result.
- The system message, your messages and the model's messages (tool calls included) are never changed. No message is removed.

The placeholders replace the results in the agent's history, so `agent.history` shows them too.

Some limits to be aware of:

- **The check happens only at the start of a turn.** A turn that goes past the limit runs to the end unchanged, and the next turn starts shortened. This is because, from Claude 5.1 on, the API can reject a request if anything before a thinking block has changed ([Keeping the prefix unchanged](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking#prefix-check)).
- **It relies on the model reporting usage.** A reply without `usage` leaves the last count in place, so a model that never reports usage (such as a custom model that leaves it out) never triggers the limit.
- **Only tool results are replaced.** If your messages and the model's messages alone pass the limit, the history keeps growing.

## How the image cap works

At the start of each turn, if tool results hold more than `max_images` images, the oldest are replaced with `[image from an earlier turn removed]` until `preserve_recent_images` remain.

- Only images in tool results count: screenshots, images read with `imgread`, images an MCP tool returns. Images you attach to your own messages are never replaced.
- Nothing is replaced during a turn, so a turn with many screenshots sends them all until the next turn starts.
- The cap counts images across all turns, including the most recent ones.

## Large images are resized

Separately from the cap, and for every model, any embedded image larger than 2576 pixels on its longer edge is resized to 2576 before it enters the history. This applies to images you attach and images tools return. The resized image is rotated upright using its EXIF orientation and keeps its color profile. Its format:

| Original image | Saved as |
| --- | --- |
| Anything except WebP | The same format |
| WebP with transparency | PNG |
| Lossless WebP without transparency | PNG, or JPEG if the PNG would be over 5 MB in base64 |
| Any other WebP | JPEG |
| Animated images, GIFs, and images still over 5 MB in base64 after resizing | Left unchanged |
