`.browser()` on the `AgentBuilder` gives an agent `browser_*` tools to open pages, read them, click, type and take screenshots. Your program controls the browser over the Chrome DevTools Protocol (CDP), so the agent doesn't need a sandbox to browse.

There are two kinds of browser:

| | Your own browser (default) | A separate browser (`isolated`) |
| --- | --- | --- |
| Signed in to your accounts | Yes | No, unless you keep a `profile` |
| Asks your permission | Yes, once per agent | No |
| Setup | Turn on remote debugging | A Chromium-based browser installed on the machine |

Both need a Chromium-based browser: Chrome, Chromium, Edge or Brave.

## Use your own browser

1. **Turn on remote debugging.** In Chrome 144 or later, open `chrome://inspect/#remote-debugging` and turn it on.
2. **Build the agent with `.browser()`** (`Browser::user()` in Rust):

```python
import asyncio

from ailoy import AgentBuilder


async def main() -> None:
    agent = await AgentBuilder("anthropic/claude-sonnet-5-5").browser().build()

    async for output in agent.run("Open https://example.com and tell me its title."):
        for part in output["message"]["contents"]:
            if part["type"] == "text":
                print(part["text"])

    await agent.close()


asyncio.run(main())
```

3. **Allow the connection.** Nothing connects until the agent first uses a browser tool. Your browser then asks whether to allow it. Once allowed, the agent opens its own window and works there, and Chrome shows that it's controlled by automated software. The browser asks only once per agent, because Ailoy keeps the connection open.

To ask for permission at a time that suits you, for example while you're at your screen, call `start_browser()` (`startBrowser()` in Node.js) between turns. It does nothing if already connected, and raises an error if you decline or remote debugging is off. To choose the page the agent's window opens on, pass `start_url` (`startUrl` in Node.js, `Browser::start_url` in Rust).

What happens when something goes wrong:

- **You decline.** The agent is told and doesn't try again in that turn. If your next message asks it to, its next browser tool asks you again.
- **The browser closes or remote debugging is turned off.** The agent reconnects on its next browser tool. The browser asks again, and the agent opens a new window if its old one is gone. The agent is told when this happens.
- **Remote debugging is off.** The agent is told how to turn it on, so it can tell you.

### Choose which browser

Ailoy finds your browser through the `DevToolsActivePort` file that a Chromium-based browser writes while remote debugging is on. By default it checks Chrome (stable, Beta, Dev and Canary), Chromium, Edge and Brave, and uses whichever turned on remote debugging most recently.

To pick one, pass `user_browser` (`userBrowser` in Node.js, `Browser::user_browser` in Rust): `"chrome"`, `"chrome-beta"`, `"chrome-dev"`, `"chrome-canary"`, `"chromium"`, `"edge"` or `"brave"`. For any other Chromium-based browser, pass its user data directory: a path in Python, `{ userDataDir }` in Node.js, `UserBrowser::Custom` in Rust.

:::caution
The agent uses your real browser, signed in to your accounts. It can't reach your other tabs, but in its own window it can do anything you can. The tool descriptions tell it to ask you before anything that can't be undone, such as paying, sending or deleting. That is an instruction to the model, not an enforced limit, so only use your own browser with an agent and a task you trust.
:::

## Use a separate browser

With `isolated=True` (`isolated: true` in Node.js, `Browser::isolated()` in Rust), the agent gets its own browser, separate from yours. Ailoy starts it on first use and closes it when the agent closes. You don't need to turn on remote debugging, and it doesn't ask for permission.

- **Which browser:** the one at `executable` if you pass it. Otherwise the first Chromium-based browser found on the machine: Chrome, Chromium, Edge or Brave. If none is installed, it fails to start.
- **Profile:** a fresh profile that is deleted afterwards, so it's not signed in anywhere. Pass `profile` with a user data directory to keep sign-ins between runs.
- **Window:** it opens a window, where you can sign in when the agent asks you to. Pass `headless` to run without a window, for example on a server. Then the agent can only tell you what a site needs.
- **If it closes:** the next browser tool starts it again with the same profile, and the agent is told its tabs are gone.

`user_browser` only applies to your own browser, and `headless`, `executable` and `profile` only to a separate one. Mixing them fails when the agent is built.

## Browser tools reference

The agent isn't sent the page at every step. It reads the page with `browser_snapshot` when it needs to.

| Tool | What it does |
|---|---|
| `browser_navigate` | Opens a URL in the current tab, or in a new one with `new_tab`. |
| `browser_back` | Goes back one page. |
| `browser_snapshot` | The page as text: first a line on the page as a whole (links, refs, iframes, how much lies above and below, whether it still loads), then its accessibility tree in document order, frames included (those of other sites too). What can be acted on has a ref such as `[ref=e3]`; what is hidden or covered is left out, a box that scrolls says how far, and a select lists its options. `interactive` keeps only what can be acted on, `depth` limits the tree, `selector` keeps one element and what is inside it, `urls` shows where links go. |
| `browser_click` | Clicks an element by ref, at its middle, by script when something covers it; or at `x` and `y` in the last screenshot. A `<select>` gives its options instead, and a download the click starts is waited for and reported. |
| `browser_input` | Types into a field by ref a key at a time, clearing it first unless `clear` is false; a date, time or color field is set outright. Says when the field ends up holding something else. |
| `browser_send_keys` | Presses a key or a shortcut, such as `Enter` or `Control+a`, or types text into what has focus. |
| `browser_scroll` | Scrolls by pages, the page or inside an element by ref (an iframe's document, or the box under it). |
| `browser_find_text` | Scrolls to the first element whose text or an attribute holds some text. |
| `browser_dropdown_options` | Lists a dropdown's options: a `<select>`, an ARIA combobox, menu or listbox, or a Semantic UI dropdown. |
| `browser_select_dropdown` | Picks a dropdown's option by its text or value, case ignored. |
| `browser_search_page` | Searches the page's text, like grep, with the text around each match and the element it is in. |
| `browser_find_elements` | Queries elements by CSS selector, with their text, the attributes asked for and how many children they have. |
| `browser_evaluate` | Runs JavaScript in the page and returns its value; an image it returns as a data URL is shown as one. |
| `browser_screenshot` | A picture of the current tab, at most 1280 pixels wide; `browser_click`'s coordinates are its pixels. Old screenshots are capped as in [How the image cap works](/docs/guides/context-manager/#how-the-image-cap-works). |
| `browser_wait` | Waits for text to appear, or for some seconds. |
| `browser_dialog` | Accepts or dismisses a confirm, or answers a prompt. An alert is accepted on its own, and the agent is told. |
| `browser_tabs` | Lists the agent's tabs, by id. |
| `browser_switch_tab`, `browser_close_tab` | Switches to or closes one of them. |

If the agent also has a sandbox, it gets four more tools that move files between the browser and the sandbox. `browser_save_screenshot` and `browser_save_as_pdf` save the current tab in the sandbox as a PNG or a PDF; the PDF is named after the page unless the agent gives a name, with paper, orientation, scale and margins as asked. `browser_upload_file` puts a sandbox file into a file input, the one by ref or the nearest one. `browser_save_download` copies a file the agent's tabs downloaded (up to 512 MiB) into the sandbox. Downloads themselves go where your browser puts them.

A ref points to the same element as long as the page shows the same document. Elements that appeared since the last snapshot are marked `[new]`. After navigating, the agent takes a new snapshot. Each action reports the page's title and address afterwards, and a tab the page opens becomes the agent's current tab.

The tools only reach the agent's own tabs: the ones it opened, and the ones its pages opened.

## Sites that check for bots

Some sites block traffic that looks automated. By default, the `browser_navigate` tool tells the agent to use sites as a person would: start from the home page or search, follow links and forms instead of typing query URLs, act at a person's pace, and never retry in a loop. If a robot check appears anyway, the agent stops and tells you instead of trying to get around it. To turn this guidance off, pass `careful=False` (`careful: false` in Node.js, `Browser::careful(false)` in Rust).

Ailoy doesn't add anything about the browser to the system prompt. Everything the agent knows about it comes from the tool descriptions.

## When a site needs you

When a site needs something only you can do, such as signing in, solving a CAPTCHA or entering a second factor, the agent never asks for your password. It tells you what to do and ends its turn. Do it in the agent's window, then tell the agent to continue. It also stops and asks before anything that can't be undone.
