This page covers how to name a model, how to choose where it runs (a CLI login, the provider's API, Amazon Bedrock, OpenRouter or your own server), and how to plug in a model of your own.

## Name a model

Pass the model to `AgentBuilder` as `<org>/<name>`. Use the name the model's maker gives it: the official API id for Claude, GPT and Gemini, the Hugging Face repo id for open-weight models, or the API id for a model without a repo, such as EXAONE's `k-exaone_v2.5`. The name stays the same whichever backend runs the model, with one exception: DeepSeek's own API, the default for `deepseek-ai`, names its models without a version, so it takes DeepSeek's own names, such as `deepseek-ai/deepseek-chat`. Bedrock, OpenRouter and your own server take the Hugging Face repo id.

| Models | Org | Example |
| --- | --- | --- |
| Claude | `anthropic` | `anthropic/claude-haiku-5-5` |
| GPT | `openai` | `openai/gpt-6-luna` |
| Gemini | `google` | `google/gemini-3.1-pro` |
| DeepSeek | `deepseek-ai` | `deepseek-ai/deepseek-chat` on DeepSeek's API, `deepseek-ai/DeepSeek-V3.2` elsewhere |
| Kimi | `moonshotai` | `moonshotai/Kimi-K2-Thinking` |
| GLM | `zai-org` | `zai-org/GLM-4.6` |
| Qwen | `Qwen` | `Qwen/Qwen3-235B-A22B-Instruct-2507` |
| EXAONE | `LGAI-EXAONE` | `LGAI-EXAONE/k-exaone_v2.5` |


With the `cli` backend, the org alone (`anthropic`) runs the CLI's default model.

## Backends

A backend is how Ailoy reaches the model. Each org uses one backend at a time:

| Backend | Runs the model through | Needs |
| --- | --- | --- |
| `cli` | The org's CLI: Claude Code (`claude`), Codex (`codex`) or Gemini CLI (`gemini`) | The CLI on `PATH`, logged in |
| `api` | The org's own API | `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `DEEPSEEK_API_KEY`, `KIMI_API_KEY` (or `MOONSHOT_API_KEY`), `ZAI_API_KEY`, `DASHSCOPE_API_KEY` (Qwen) or `EXAONE_API_KEY` |
| `bedrock` | Amazon Bedrock | `AWS_BEARER_TOKEN_BEDROCK`; the region from `AWS_REGION`, then `AWS_DEFAULT_REGION`, else `us-east-1` |
| `openrouter` | OpenRouter | `OPENROUTER_API_KEY` |
| `self-hosted` | A server you run that serves the OpenAI-compatible Chat Completions API: vLLM, llama-server, Ollama, LM Studio or SGLang | `SELF_HOSTED_BASE_URL`, plus `SELF_HOSTED_API_KEY` if the server requires one |

By default, Claude, GPT and Gemini use `cli`, and the other orgs in [Name a model](#name-a-model) use `api`. Ailoy reads keys from the environment when it builds the model, so set them before you call `build()`.

`cli` and `api` support only the orgs in [Name a model](#name-a-model). `bedrock`, `openrouter` and `self-hosted` work for any org, such as `meta-llama` or `mistralai`. An org outside that table has no default backend: set one with `set_lang_model_provider` before you build its model, or the build fails. Which backends support which orgs:

| Org | `cli` | `api` | `bedrock` | `openrouter` | `self-hosted` |
| --- | :-: | :-: | :-: | :-: | :-: |
| `anthropic` | ✓ | ✓ | ✓ | ✓ | ✓ |
| `openai` | ✓ | ✓ | ✓ | ✓ | ✓ |
| `google` | ✓ | ✓ | | ✓ | ✓ |
| `deepseek-ai`, `moonshotai`, `zai-org`, `Qwen`, `LGAI-EXAONE` | | ✓ | ✓ | ✓ | ✓ |
| any other org | | | ✓ | ✓ | ✓ |

Bedrock and OpenRouter use their own model ids. You still write `anthropic/claude-haiku-5-5`: Ailoy looks the model up in their catalogs and sends the matching id. For your own server, see [Use your own model server](#use-your-own-model-server).

## Choose a backend

Call `set_lang_model_provider` (`setLangModelProvider` in Node.js) before you build the agent. The setting applies to every model of that org built afterwards, in the whole process.

<Tabs syncKey="lang">

<TabItem label="Python" icon="seti:python">

```python
import ailoy

ailoy.set_lang_model_provider("anthropic", "api")
agent = await AgentBuilder("anthropic/claude-haiku-5-5").build()
```


</TabItem>
<TabItem label="Node.js" icon="seti:javascript">

```js
const { setLangModelProvider } = require('@brekkylab/ailoy')

setLangModelProvider('anthropic', 'api')
const agent = await new AgentBuilder('anthropic/claude-haiku-5-5').build()
```


</TabItem>
<TabItem label="Rust" icon="seti:rust">

```rust
use ailoy::model::{Backend, set_lang_model_provider};

set_lang_model_provider("anthropic", Backend::Api);
let agent = AgentBuilder::new("anthropic/claude-haiku-5-5").build().await?;
```


</TabItem>
</Tabs>

`remove_lang_model_provider` (`removeLangModelProvider`) removes the org's backend. After that, its models can't be built until you set one again.

## Use your own model server

With the `self-hosted` backend set by name, Ailoy reads one server URL for the whole process from `SELF_HOSTED_BASE_URL`. To use a different server per org, pass `set_lang_model_provider` an object with the server's URL instead of the backend name. This example sends Qwen models to a vLLM server and Llama models to Ollama:

<Tabs syncKey="lang">

<TabItem label="Python" icon="seti:python">

```python
ailoy.set_lang_model_provider("Qwen", {"backend": "self-hosted", "base_url": "http://gpu-box:8000/v1", "api_key": "..."})
ailoy.set_lang_model_provider("meta-llama", {"backend": "self-hosted", "base_url": "http://localhost:11434/v1", "models": {"Llama-3.3-70B-Instruct": "llama3.3:70b"}})

coder = await AgentBuilder("Qwen/Qwen3-Coder-30B-A3B-Instruct").build()
chat = await AgentBuilder("meta-llama/Llama-3.3-70B-Instruct").build()
```


</TabItem>
<TabItem label="Node.js" icon="seti:javascript">

```js
setLangModelProvider('Qwen', { backend: 'self-hosted', base_url: 'http://gpu-box:8000/v1', api_key: '...' })
setLangModelProvider('meta-llama', { backend: 'self-hosted', base_url: 'http://localhost:11434/v1', models: { 'Llama-3.3-70B-Instruct': 'llama3.3:70b' } })

const coder = await new AgentBuilder('Qwen/Qwen3-Coder-30B-A3B-Instruct').build()
const chat = await new AgentBuilder('meta-llama/Llama-3.3-70B-Instruct').build()
```


</TabItem>
<TabItem label="Rust" icon="seti:rust">

```rust
use ailoy::model::{LangModelServer, set_lang_model_provider};

set_lang_model_provider("Qwen", LangModelServer::new("http://gpu-box:8000/v1")?.with_api_key("..."));
set_lang_model_provider("meta-llama", LangModelServer::new("http://localhost:11434/v1")?.with_model("Llama-3.3-70B-Instruct", "llama3.3:70b"));

let coder = AgentBuilder::new("Qwen/Qwen3-Coder-30B-A3B-Instruct").build().await?;
let chat = AgentBuilder::new("meta-llama/Llama-3.3-70B-Instruct").build().await?;
```


</TabItem>
</Tabs>

You keep the model's usual name, even if the server calls it something else. When the model is built, Ailoy picks the id to send to the server from the first of these that matches:

1. The `models` map (`with_model` in Rust), which maps a model name to the server's id.
2. The server's model list at `<base_url>/models`: an id equal to `<org>/<name>`, or to `<name>` alone, ignoring case.
3. The name exactly as you wrote it.

So vLLM, which serves Hugging Face repo ids, needs no mapping. LM Studio lists `qwen/qwen3-0.6b`, which matches `Qwen/Qwen3-0.6B` in step 2. Ollama's `llama3.3:70b` doesn't match `Llama-3.3-70B-Instruct`, so it needs the `models` map, as in the example. For these orgs, `get_lang_model_provider` returns `self-hosted`.

Any other endpoint that serves the OpenAI-compatible Chat Completions API, such as a LiteLLM gateway or Together's API, works the same way: pass its URL as `base_url` and its key as `api_key`.

## Model options

These two options work on every backend:

| Option | Builder method | Description |
| --- | --- | --- |
| `thinking_effort` | `thinking_effort` (`thinkingEffort`) | How much the model reasons before answering: `low`, `medium` or `high`. If unset, the model's default. |
| `output_schema` | `output_schema` (`outputSchema`) | A JSON schema the model's answers must match. |

<Tabs syncKey="lang">

<TabItem label="Python" icon="seti:python">

```python
agent = await (
    AgentBuilder("openai/gpt-6-luna")
    .thinking_effort("high")
    .output_schema({"type": "object", "properties": {"answer": {"type": "string"}}, "required": ["answer"]})
    .build()
)
```


</TabItem>
<TabItem label="Node.js" icon="seti:javascript">

```js
const agent = await new AgentBuilder('openai/gpt-6-luna')
  .thinkingEffort('high')
  .outputSchema({ type: 'object', properties: { answer: { type: 'string' } }, required: ['answer'] })
  .build()
```


</TabItem>
<TabItem label="Rust" icon="seti:rust">

```rust
use ailoy::{model::ThinkingEffort, to_value};

let agent = AgentBuilder::new("openai/gpt-6-luna")
    .thinking_effort(ThinkingEffort::High)
    .output_schema(to_value!({"type": "object", "properties": {"answer": {"type": "string"}}, "required": ["answer"]}))
    .build()
    .await?;
```


</TabItem>
</Tabs>

### How self-hosted servers handle these options

On `self-hosted`, and for EXAONE on `api`, Ailoy sends `thinking_effort` in two forms, because servers read different fields: as `reasoning_effort` (`low`, `medium` or `high`), and as `enable_thinking` (and `thinking`) in `chat_template_kwargs`. `output_schema` is sent as a `json_schema` `response_format`. vLLM reads `chat_template_kwargs` and `response_format`, and its documentation says it passes `reasoning_effort` to the chat template.

Results for other servers, measured on 2026-11-09 with Qwen3-0.6B on each local server and `k-exaone_v2.5` on EXAONE's API:

| Server | `reasoning_effort` | `chat_template_kwargs` | `response_format` | Thinking comes back as |
| --- | --- | --- | --- | --- |
| llama-server (llama.cpp build 11146) | Not read: `"bogus"` is accepted too | Read: `enable_thinking: false` switched the thinking off | Enforced | `reasoning_content` |
| Ollama 0.40.12 | Read, as `"bogus"` is refused, but `low`, `medium` and `high` left Qwen3's thinking as it was | Ignored | Enforced | `reasoning` |
| LM Studio 0.4.26 | Read, as `"bogus"` is refused, but `low`, `medium` and `high` left Qwen3's thinking as it was | Ignored | Enforced, with no thinking while the reply is structured | `reasoning_content` |
| EXAONE API (`k-exaone_v2.5`) | Read, as `"bogus"` is refused, `medium` included; on one counting problem the thinking did not follow it, `low` taking 991 to 1728 reasoning tokens over six runs and `high` 1054 to 2131 over four | `enable_thinking: false` left the model thinking, with the thinking and its `</think>` in the reply | Enforced | `reasoning_content` |

In short: with Qwen3, `thinking_effort` has no effect on llama-server, Ollama or LM Studio; the model reasons as its chat template defaults. EXAONE always reasons, and with `thinking_effort` unset it uses its own default effort, which its documentation gives as `max`. SGLang hasn't been tested.

## Call a model without an agent

`LangModel` builds a model the same way an agent does and runs it on messages you pass. It doesn't call tools or keep a history. `infer` returns the whole reply as a `MessageOutput`, and `infer_stream` (`inferStream`) returns `MessageDeltaOutput`s as the model writes.

<Tabs syncKey="lang">

<TabItem label="Python" icon="seti:python">

```python
from ailoy import LangModel

model = await LangModel.create("anthropic/claude-haiku-5-5")
messages = [{"role": "user", "contents": [{"type": "text", "text": "Hi"}]}]

output = await model.infer(messages)
async for delta in model.infer_stream(messages, options={"thinking_effort": "low"}):
    ...
```


</TabItem>
<TabItem label="Node.js" icon="seti:javascript">

```js
const { LangModel } = require('@brekkylab/ailoy')

const model = await LangModel.create('anthropic/claude-haiku-5-5')
const messages = [{ role: 'user', contents: [{ type: 'text', text: 'Hi' }] }]

const output = await model.infer(messages)
for await (const delta of model.inferStream(messages, [], { thinking_effort: 'low' })) {
  // ...
}
```


</TabItem>
<TabItem label="Rust" icon="seti:rust">

```rust
use ailoy::{
    message::{Message, Part, Role},
    model::{LangModelOptions, create_lang_model},
};

let model = create_lang_model("anthropic/claude-haiku-5-5").await?;
let messages = [Message::new(Role::User).with_contents([Part::text("Hi")])];

let output = model.infer(&messages, &[], &LangModelOptions::default()).await?;
let mut deltas = model.infer_stream(&messages, &[], &LangModelOptions::default());
```


</TabItem>
</Tabs>

If you pass tools, they are only described to the model. Any tool calls come back in the reply for you to run.

## Use a custom model

You can serve an org with your own code. Pass `set_lang_model_provider` a **factory** instead of a backend name. Ailoy calls the factory with the org and the name after the slash (`None` in Python, `null` in Node.js, when the model is named by its org alone). The factory returns a model with:

- `infer(messages, tools, options)`, which returns a `MessageOutput`. In Python and Node.js it can also return an awaitable or a promise of one.
- Optionally, `infer_stream(messages, tools, options)` (`inferStream`), which yields `MessageDeltaOutput`s. Without it, streaming returns `infer`'s reply as a single delta.

The factory can also return a `LangModel`, to serve the org with another org's model.

<Tabs syncKey="lang">

<TabItem label="Python" icon="seti:python">

```python
class Echo:
    def __init__(self, name):
        self.name = name

    async def infer(self, messages, tools, options):
        text = messages[-1]["contents"][0]["text"]
        return {
            "message": {"role": "assistant", "contents": [{"type": "text", "text": text}]},
            "finish_reason": {"type": "stop"},
        }

ailoy.set_lang_model_provider("mine", lambda org, name: Echo(name))
agent = await AgentBuilder("mine/echo").build()
```


</TabItem>
<TabItem label="Node.js" icon="seti:javascript">

```js
class Echo {
  constructor(name) {
    this.name = name
  }
  async infer(messages, tools, options) {
    const text = messages[messages.length - 1].contents[0].text
    return {
      message: { role: 'assistant', contents: [{ type: 'text', text }] },
      finish_reason: { type: 'stop' },
    }
  }
}

setLangModelProvider('mine', (org, name) => new Echo(name))
const agent = await new AgentBuilder('mine/echo').build()
```


</TabItem>
<TabItem label="Rust" icon="seti:rust">

```rust
use std::sync::Arc;

use ailoy::{
    message::{FinishReason, Message, MessageDeltaOutput, MessageOutput, Role},
    model::{InferLangModel, LangModelOptions, LangModelProvider, set_lang_model_provider},
    tool::ToolDesc,
};
use futures::{future::BoxFuture, stream::{self, BoxStream}, StreamExt as _};

struct Echo;

impl InferLangModel for Echo {
    fn infer(
        &self,
        messages: &[Message],
        _tools: &[ToolDesc],
        _options: &LangModelOptions,
    ) -> BoxFuture<'static, anyhow::Result<MessageOutput>> {
        let contents = messages.last().map(|m| m.contents.clone()).unwrap_or_default();
        Box::pin(async move {
            Ok(MessageOutput {
                message: Message::new(Role::Assistant).with_contents(contents),
                finish_reason: FinishReason::Stop {},
                usage: None,
            })
        })
    }

    fn infer_stream(
        &self,
        messages: &[Message],
        tools: &[ToolDesc],
        options: &LangModelOptions,
    ) -> BoxStream<'static, anyhow::Result<MessageDeltaOutput>> {
        let output = self.infer(messages, tools, options);
        stream::once(async move { output.await.map(MessageDeltaOutput::from) }).boxed()
    }
}

set_lang_model_provider("mine", LangModelProvider::custom(|_org, _name| Ok(Arc::new(Echo))));
let agent = AgentBuilder::new("mine/echo").build().await?;
```


</TabItem>
</Tabs>

In Python and Node.js, the factory itself must return the model directly, not an awaitable or a promise. The model's methods receive the messages, tools and options as dicts (Python) or objects (Node.js), in the shapes [Messages](/docs/guides/message-format/) describes.

## Troubleshooting

| Error | Cause and fix |
| --- | --- |
| `failed to start the claude CLI` (or `codex`, `gemini`), on the first turn | The CLI isn't installed, or isn't on the `PATH` of your program. Install it ([Option A: log in to a CLI](/docs/guides/installation/#option-a-log-in-to-a-cli-no-api-key)), or switch the org to `api`. |
| The CLI's own error on the first turn, such as Claude Code's "Not logged in" | Log in: `claude auth login`, `codex login`, or run `gemini` and sign in. Codex is read from its `auth.json`, so a login kept in the system keyring (`cli_auth_credentials_store`) isn't found. |
| `ANTHROPIC_API_KEY is not set` (or another `…_API_KEY`), at `build()` | Set the variable before building the agent; a blank one counts as unset. [Backends](#backends) lists each org's variable. |
| `'<org>' has no CLI`, or `'<org>' has no API of its own` | Only `anthropic`, `openai` and `google` have a CLI, and `api` knows only the orgs in [Name a model](#name-a-model). Use `bedrock`, `openrouter` or `self-hosted` for any other. |
| `no provider set for lang model org '<org>'` | The org has no default backend. Set one with `set_lang_model_provider` first. |
| `AWS_BEARER_TOKEN_BEDROCK is not set` | Bedrock is reached with a bearer token, not AWS access keys or a profile. Set the token. |
| `Bedrock request failed with status …` on the first turn | The region is wrong, as `us-east-1` is used when neither `AWS_REGION` nor `AWS_DEFAULT_REGION` is set, or Bedrock doesn't serve the model there. Ailoy builds an id for any model, so a model Bedrock lacks, such as Gemini, fails only when it is called. |
| `SELF_HOSTED_BASE_URL is not set` | Set it, or give the server per org with `set_lang_model_provider` ([A server of your own](#use-your-own-model-server)). |
| `chat completions request failed with status 404: …` | The `base_url` is missing its `/v1`. Ailoy adds `/chat/completions` to the URL as given. |
| A connection error naming `<base_url>/chat/completions` on the first turn | The server isn't running, or the host or port is wrong. `build()` still succeeds and only logs `listing the models at <base_url>/models failed`. |
