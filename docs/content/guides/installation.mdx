Setup takes three steps: check that your machine can run a sandbox, install the package for your language, and give Ailoy access to a model. Pick your language in the first tab you see. Every other tab on these pages switches with it.

<div class="steps-flow">

## Check the requirements

You need one of these language versions:

| Language | Version |
| --- | --- |
| Python | 3.11 or later |
| Node.js | 22 or later |
| Rust | 1.95 or later |

To give an agent a sandbox, the machine that runs the sandbox must support microVMs. That is your own machine unless you run the sandbox server somewhere else.

| OS | What you need |
| --- | --- |
| Linux | KVM, with `/dev/kvm` open to your user and virtualization turned on in the firmware. Most kernels include KVM. |
| macOS | Apple silicon. Intel Macs can't run sandboxes. |
| Windows | Windows 11 or later, with the Windows Hypervisor Platform turned on (see below). |

An agent without a sandbox runs on any machine. You can skip the OS requirements if you only want to try a model and tools first.

### Turn on the Windows Hypervisor Platform

The Hypervisor Platform is off by default. Make sure virtualization is turned on in the firmware, then run this in PowerShell as administrator and restart:

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName HypervisorPlatform
```

## Install the package

<Tabs syncKey="lang">

<TabItem label="Python" icon="seti:python">

```sh
pip install ailoy-py
```

This also installs `virtx`, the package you use to create sandboxes.

</TabItem>
<TabItem label="Node.js" icon="seti:javascript">

```sh
npm install @brekkylab/ailoy
```

This also installs `@brekkylab/virtx`, the package you use to create sandboxes. If you use pnpm, add `@brekkylab/virtx` yourself, because pnpm only lets your code import packages you list.

</TabItem>
<TabItem label="Rust" icon="seti:rust">

In a Cargo project (`cargo new my-agent && cd my-agent` makes one):

```sh
cargo add ailoy virtx futures anyhow tokio --features tokio/macros,tokio/rt-multi-thread
```

`virtx` is the crate you use to create sandboxes. Add it next to `ailoy`, because Cargo only lets your code use crates you list. The code on these pages also uses `tokio`, `futures` and `anyhow`.

</TabItem>
</Tabs>

You don't install the sandbox server yourself. The first time your code calls `Client.spawn()` (`Client::spawn_virtx` in Rust), virtx downloads the server into its cache.

## Set up a model

Every agent needs a model. Choose one of two options.

### Option A: log in to a CLI (no API key)

Claude, GPT and Gemini models run through their official CLIs by default. If you already use one of these CLIs, you don't need an API key. Install the CLI for your model and log in:

| Model | CLI | Log in | Check the login |
| --- | --- | --- | --- |
| Claude | [Claude Code](https://docs.anthropic.com/en/docs/claude-code) | `claude auth login` | `claude auth status` |
| GPT | [Codex](https://github.com/openai/codex) | `codex login` | `codex login status` |
| Gemini | [Gemini CLI](https://github.com/google-gemini/gemini-cli) | Run `gemini` and sign in | |

The examples in these docs use `anthropic/claude-haiku-5-5`, so Claude Code is the CLI to install if you want to run them as written.

### Option B: use an API key

Set the key for your model's provider:

```sh
export ANTHROPIC_API_KEY=...   # or OPENAI_API_KEY, GEMINI_API_KEY
```

Then tell Ailoy to use the API for that provider. Run this once, before you build an agent:

<Tabs syncKey="lang">

<TabItem label="Python" icon="seti:python">

```python
import ailoy

ailoy.set_lang_model_provider("anthropic", "api")
```

</TabItem>
<TabItem label="Node.js" icon="seti:javascript">

```js
const { setLangModelProvider } = require('@brekkylab/ailoy')

setLangModelProvider('anthropic', 'api')
```

</TabItem>
<TabItem label="Rust" icon="seti:rust">

```rust
ailoy::model::set_lang_model_provider("anthropic", ailoy::model::Backend::Api);
```

</TabItem>
</Tabs>

Other providers (DeepSeek, Kimi, GLM, Qwen, EXAONE), Amazon Bedrock, OpenRouter and your own model server are covered in [Model providers](/docs/guides/model-providers/).

## Troubleshooting

| Error | Cause | Fix |
| --- | --- | --- |
| `boot_failed` when you create a sandbox | This machine can't start a VM. | **Linux:** run `sudo usermod -aG kvm $USER`, then log out and back in. **Windows:** turn on the [Hypervisor Platform](#turn-on-the-windows-hypervisor-platform). **Any OS:** turn on virtualization (Intel VT-x or AMD-V) in the firmware. To see the hypervisor's own messages, set `KRUN_LOG=debug`. |
| `no virtx-stdio release … for macos-x86_64` | Sandboxes run on Apple silicon only, not on Intel Macs. | Run the sandbox server on another machine and connect to it. See virtx's [Hello world](https://virtx.sh/docs/hello-world/). |
| `fetching …/virtx/releases/…` on the first `Client.spawn()` | The server download failed. | Check your network or proxy. You can also set `VIRTX_DIST_URL` to a mirror, or download the server yourself and set `VIRTX_STDIO` to its path ([Environment variables](https://virtx.sh/docs/reference/api/#environment-variables)). |
| `… does not match its SHA256SUMS` | The download was changed on the way, often by a proxy. | Try again, or set `VIRTX_STDIO` as above. |
| "Not logged in", or another CLI or API error on the first turn | The model isn't set up. | Log in to the CLI (Option A) or set the API key (Option B). See also [Model providers troubleshooting](/docs/guides/model-providers/#troubleshooting). |
