Tools are functions the model can call. An agent has only the tools you give it on the `AgentBuilder`:

| Tools | How to add them | Where they run |
| --- | --- | --- |
| [Shell and file tools](#shell-and-file-tools) | `.sandbox(sandbox)` | In the sandbox |
| [Web search and fetch](#web-search-and-fetch) | `.web_search_tool()`, `.web_fetch_tool()` | In your program |
| [Your own functions](#add-your-own-function) | `register_tool(...)`, then `.tool(desc)` | In your program |
| [MCP server tools](/docs/guides/using-mcp/) | `register_mcp_stdio(...)`, then `.tools(descs)` | Where the MCP server runs |
| [Browser tools](/docs/guides/using-browser/) | `.browser()` | In your program, controlling a browser |
| [The memory tool](/docs/guides/memory/) | `.memory(dir)` | In your program |

## Shell and file tools

An agent with a sandbox gets a shell and tools to read and edit files in it. You don't add them yourself. The exact set depends on the model's org, so each model gets tools in the shape it was trained on:

| Org | Tools |
| --- | --- |
| `openai` | `shell`, `apply_patch`, `imgread` |
| `google` | `shell`, `read_file`, `write`, `edit`, `imgread` |
| `deepseek-ai`, `moonshotai`, `zai-org`, `Qwen`, `LGAI-EXAONE` | `shell`, `read`, `write`, `edit` |
| Any other, including `anthropic` | `shell`, `read`, `write`, `edit`, `imgread` |

| Tool | What it does |
| --- | --- |
| `shell` | Runs a command, with an optional timeout in seconds. |
| `read` | Reads up to 2,000 numbered lines of a text file, or `limit` lines starting at line `offset`. |
| `read_file` | Reads up to 2,000 lines of a text file, or the lines from `start_line` to `end_line`. |
| `write` | Writes a text file, replacing any file already at that path. |
| `edit` | Replaces an exact string that occurs once in a text file, or every occurrence with `replace_all`. |
| `apply_patch` | Adds, deletes, updates and moves files using a patch in Codex's format. |
| `imgread` | Reads a PNG, JPEG, GIF or WebP image up to 5 MB and shows it to the model. |

`imgread` isn't given to `deepseek-ai`, `moonshotai`, `zai-org`, `Qwen` and `LGAI-EXAONE` models, because their backends pass tool results as text, so the model would see a label instead of the image.

When the sandbox has been idle, virtx stops its VM and starts it again on the next tool call. Files stay as the last call left them.

## Web search and fetch

`web_search_tool` and `web_fetch_tool` (`webSearchTool`, `webFetchTool`) add two tools that run in your program, not in the sandbox, so they work with or without one.

- **`web_search`** sends the query to several search engines at once, merges the results (one per URL, best first) and returns up to 10, or up to 30 when the model asks for more. Pass a list of engines to use: `Bing`, `Brave`, `DuckDuckGo`, `Google`, `Mojeek`, `Naver`, `Startpage`, `Yahoo` and `Yandex`. No list, or an empty one, uses all of them.
- **`web_fetch`** fetches one URL. An HTML page comes back as its visible text by default, or as Markdown or raw HTML. Other content, such as JSON, comes back as it is. A long page comes back in pieces, and the model asks for the next one with `offset`. Only the first 2 MiB are read. It makes at most one request per second to each host, and only to public internet addresses: loopback, local network and cloud metadata addresses are refused.

## Add your own function

To turn a function into a tool:

1. **Describe it.** Write a tool description with the name the model calls it by, what it does, and a JSON schema for its arguments.
2. **Register it.** Register the description together with the function. In Python and Node.js, `register_tool` returns the description. In Rust, build the description with `ToolDescBuilder` and register the function under the same name with `set_tool_provider`.
3. **Give it to the agent** with `.tool(desc)`, or a list with `.tools(descs)`.

This example gives the agent an `order_status` tool that looks up an order by its id:

<Tabs syncKey="lang">

<TabItem label="Python" icon="seti:python">

```python
import asyncio

from ailoy import AgentBuilder, register_tool

ORDERS = {"A-1001": {"status": "shipped", "eta": "2026-10-24"}}


def order_status(order_id: str) -> dict:
    if order_id not in ORDERS:
        raise KeyError(f"no order {order_id}")
    return ORDERS[order_id]


async def main() -> None:
    desc = register_tool(
        {
            "name": "order_status",
            "description": "Look up an order's status and expected delivery date by its id.",
            "parameters": {
                "type": "object",
                "properties": {"order_id": {"type": "string", "description": "The order id, such as A-1001"}},
                "required": ["order_id"],
            },
        },
        order_status,
    )

    agent = await AgentBuilder("anthropic/claude-haiku-5-5").tool(desc).build()

    async for output in agent.run("When does order A-1001 arrive?"):
        for part in output["message"]["contents"]:
            if part["type"] == "text":
                print(part["text"])


asyncio.run(main())
```

</TabItem>
<TabItem label="Node.js" icon="seti:javascript">

```js
const { AgentBuilder, registerTool } = require('@brekkylab/ailoy')

async function main() {
  const orders = { 'A-1001': { status: 'shipped', eta: '2026-10-24' } }

  const desc = registerTool(
    {
      name: 'order_status',
      description: "Look up an order's status and expected delivery date by its id.",
      parameters: {
        type: 'object',
        properties: { order_id: { type: 'string', description: 'The order id, such as A-1001' } },
        required: ['order_id'],
      },
    },
    ({ order_id }) => {
      if (!(order_id in orders)) throw new Error(`no order ${order_id}`)
      return orders[order_id]
    },
  )

  const agent = await new AgentBuilder('anthropic/claude-haiku-5-5').tool(desc).build()

  try {
    for await (const { message } of agent.run('When does order A-1001 arrive?')) {
      for (const part of message.contents) {
        if (part.type === 'text') console.log(part.text)
      }
    }
  } finally {
    await agent.close()
  }
}

main()
```

<TabItem label="Rust" icon="seti:rust">

```rust
use ailoy::{
    agent::AgentBuilder,
    datatype::Value,
    message::{Message, Part, Role},
    to_value, tool_func,
    tool::{ToolDescBuilder, set_tool_provider},
};
use futures::StreamExt as _;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let desc = ToolDescBuilder::new("order_status")
        .description("Look up an order's status and expected delivery date by its id.")
        .parameters(to_value!({
            "type": "object",
            "properties": {"order_id": {"type": "string", "description": "The order id, such as A-1001"}},
            "required": ["order_id"]
        }))
        .build();
    set_tool_provider(
        "order_status",
        tool_func!(|args: Value| -> Value {
            match args.pointer("/order_id").and_then(Value::as_str) {
                Some("A-1001") => to_value!({"status": "shipped", "eta": "2026-10-24"}),
                Some(id) => Value::string(format!("error: no order {id}")),
                None => Value::string("error: no order_id"),
            }
        }),
    );

    let mut agent = AgentBuilder::new("anthropic/claude-haiku-5-5")
        .tool(desc)
        .build()
        .await?;

    let query = Message::new(Role::User).with_contents([Part::text("When does order A-1001 arrive?")]);
    let mut stream = agent.run(query);
    while let Some(output) = stream.next().await {
        let message = output?.message;
        if message.role == Role::Assistant {
            for text in message.contents.iter().filter_map(Part::as_text) {
                println!("{text}");
            }
        }
    }
    Ok(())
}
```

### How your function is called

| Language | Arguments | Async |
| --- | --- | --- |
| Python | Keyword arguments, named as in the schema | The function can be `async` |
| Node.js | One object | The function can return a promise |
| Rust | A `Value`, in a closure passed to `tool_func!` | Put `async` before the closure to use `.await` in its body |

Your function must return JSON-compatible data: null, a boolean, a number, a string, or a list or object of those.

If a Python or Node.js function raises an exception (or its promise rejects), the run continues. The model receives the error as the result, for example `error: KeyError: 'no order B-9'`, and can try something else.

Tool calls the model makes in one step run at the same time, so your function may be called again before an earlier call has returned.

### Run commands in the sandbox from your function

A Python or Node.js tool function runs in your program, not in the sandbox. To run a command or read a file in the sandbox, call the virtx `Sandbox` object you created, for example `sandbox.exec(...)` or `sandbox.read_file(...)`. In Rust, a closure that also takes `sandbox: &Sandbox` receives the agent's sandbox, and `ailoy::tool::{exec, read, write}` run commands and read and write files in it.

### Replace or remove a tool

Tools are registered by name for the whole process, including the built-in ones. Registering a name again replaces its function for every agent built afterwards, even a built-in like `shell`. The one exception is `web_search` on an agent given a non-empty list of engines, which builds its own.

- `set_tool_provider(name, func)` (`setToolProvider`) replaces only the function. Use it when a saved spec already has the tool's description.
- `remove_tool_provider(name)` (`removeToolProvider`) removes the tool.

## How long tool results are handled

The agent keeps at most 30,000 characters of each part of a tool result, for built-in tools and your own:

- A longer part keeps its first and last 15,000 characters, with a note in between saying how many were cut. A large file read in one call can reach the model with its middle missing.
- A Python or Node.js function's result, including a string, becomes a `value` part. Its size is measured in characters of JSON. Past 30,000, the model receives the JSON as text with the middle cut.
- `web_fetch` and `shell` size their own results: a long page comes in pieces that each fit, and `shell` cuts long output itself, keeping the start and end.
