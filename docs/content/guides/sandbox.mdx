import { Tabs, TabItem } from '@astrojs/starlight/components';

The computer an agent works on is a sandbox: a Linux microVM on a [virtx](https://virtx.sh/docs/) server. Your code gives Ailoy a client of that server, made with virtx's own package, and Ailoy makes each agent's sandbox there as the agent is made, and removes it as the agent closes:

- **Python:** the `virtx` package (`import virtx`), which `pip install ailoy-py` installs too
- **Node.js:** `@brekkylab/virtx`, which `npm install @brekkylab/ailoy` installs too
- **Rust:** the `virtx` crate, added beside `ailoy` (`ailoy::console::Sandbox` is `virtx::Sandbox`)

This page covers what an agent needs from a sandbox. [virtx's docs](https://virtx.sh/docs/) cover the sandbox itself: servers, images, volumes and GPUs.

## Making an agent's sandbox

`set_virtx(client)` (`setVirtx` in Node.js; the default provider's `virtx` in Rust) gives Ailoy the virtx client it makes sandboxes with. A spec with `use_sandbox` then works in a sandbox made as `from_spec`'s `sandbox` says, and gets a shell and file tools that run there; [Tools](/docs/guides/tools/#a-shell-and-files) lists them. Here an image with matplotlib is built on the server, an agent's sandbox is made from it, and the agent's chart is read out of the sandbox before the agent closes:

<Tabs syncKey="lang">

<TabItem label="Python" icon="seti:python">

```python
import asyncio
from pathlib import Path

import ailoy
from ailoy import Agent
from virtx import Client, Recipe


async def main() -> None:
    client = Client.spawn()
    ailoy.set_virtx(client)

    # Kept on the server under its tag: later sandboxes boot it without building again.
    recipe = Recipe("python:3.12-slim-trixie").run("pip install --no-cache-dir matplotlib")
    await client.build_image(recipe, "plot:latest").complete()

    agent = await Agent.from_spec(
        {
            "model": "anthropic/claude-haiku-5-5",
            "instruction": "Write what you are asked for into /artifacts.",
            "use_sandbox": True,
        },
        sandbox={"create": {"image": {"type": "tag", "tag": "plot:latest"}}},
    )
    async for _ in agent.run("Plot y = x^2 for x from -5 to 5 into /artifacts/square.png."):
        pass

    sandbox = await client.get_sandbox(agent.sandbox_id)
    Path("square.png").write_bytes(await sandbox.read_file("artifacts/square.png"))
    await agent.close()


asyncio.run(main())
```

```js
const { writeFileSync } = require('node:fs')
const { Agent, setVirtx } = require('@brekkylab/ailoy')
const { Client, Recipe } = require('@brekkylab/virtx')

async function main() {
  const client = Client.spawn()
  setVirtx(client)

  // Kept on the server under its tag: later sandboxes boot it without building again.
  const recipe = new Recipe('python:3.12-slim-trixie').run('pip install --no-cache-dir matplotlib')
  await client.buildImage(recipe, 'plot:latest').complete()

  const agent = await Agent.fromSpec(
    {
      model: 'anthropic/claude-haiku-5-5',
      instruction: 'Write what you are asked for into /artifacts.',
      use_sandbox: true,
    },
    { sandbox: { create: { image: { type: 'tag', tag: 'plot:latest' } } } },
  )
  for await (const _ of agent.run('Plot y = x^2 for x from -5 to 5 into /artifacts/square.png.'));

  const sandbox = await client.getSandbox(agent.sandboxId)
  writeFileSync('square.png', await sandbox.readFile('artifacts/square.png'))
  await agent.close()
  await client.close()
}

main()
```

<TabItem label="Rust" icon="seti:rust">

```rust
use ailoy::{
    Agent,
    agent::{AgentSpec, SessionSandbox, default_provider},
    message::{Message, Part, Role},
};
use futures::StreamExt as _;
use virtx::{Client, Files as _, Recipe, SandboxCreateArgs};

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let client = Client::spawn_virtx([] as [&str; 0]).await?;
    default_provider().write().unwrap().virtx = Some(client.clone());

    // Kept on the server under its tag: later sandboxes boot it without building again.
    let recipe = Recipe::new("python:3.12-slim-trixie").step("pip install --no-cache-dir matplotlib");
    client.build_image(recipe, "plot:latest").complete(false).await?;

    let spec = AgentSpec::new("anthropic/claude-haiku-5-5")
        .instruction("Write what you are asked for into /artifacts.")
        .sandbox();
    let sandbox = SessionSandbox::Create(SandboxCreateArgs::new("plot:latest"));
    let agent = Agent::from_spec(spec, Vec::new(), Some(sandbox)).await?;
    let query = Message::new(Role::User)
        .with_contents([Part::text("Plot y = x^2 for x from -5 to 5 into /artifacts/square.png.")]);
    let mut stream = std::pin::pin!(agent.run(&query));
    while let Some(output) = stream.next().await {
        output?;
    }

    let sandbox = client.get_sandbox(agent.sandbox_id().unwrap()).await?;
    std::fs::write("square.png", sandbox.read_file("artifacts/square.png", 0, None).await?)?;
    agent.close().await?;
    Ok(())
}
```

The sandbox is the agent's:

- Ailoy makes it as the agent is made, and removes it as the agent closes. Read what you want back before closing the agent. With a server that `Client.spawn()` started, the sandboxes also go when your program does.
- Your client reaches it by the agent's `sandbox_id` (`sandboxId` in Node.js). Your own calls on the sandbox and the agent's tool calls run side by side, and the agent's tool calls in one step run at the same time.
- A sandbox virtx refuses to make fails `from_spec` with virtx's status and message. A failed call of your own to the sandbox reaches you as virtx's `VirtxError`.

An agent without a sandbox still runs, with the tools that need none: your own functions, `web_search`, `web_fetch` and MCP servers. It has no shell or file tools, and it cannot have [skills](/docs/guides/skills/), which it reads from the sandbox. Its spec leaves `use_sandbox` out, and `from_spec` is given no sandbox.

### Of a package

`sandbox` takes one of two things:

- `{"create": args}` (`SessionSandbox::Create` in Rust): virtx's sandbox args, the image and the [options below](#sandbox-options).
- `{"package": id}` (`SessionSandbox::Package` in Rust): a virtx package, which keeps the args under a name on the server, beside who may make a sandbox of it and how many at once. virtx counts each sandbox made of it under the package.

## What lives where

A sandbox's files come from three places, and they last differently:

| Where | What it holds for the agent | How long it lasts | virtx docs |
| --- | --- | --- | --- |
| The image | The programs and packages its commands find | Until you remove the image; every sandbox booted from it starts with it | [Images](https://virtx.sh/docs/guides/images/) |
| A volume | Inputs, skills, results you want back | Until you remove the volume; several sandboxes can mount it, and your code reads and writes it while they do | [Mounting volumes](https://virtx.sh/docs/guides/mounting-volumes/) |
| The sandbox's own files | What the agent writes anywhere else, such as packages it installs | Until the agent closes, which removes the sandbox | [Removing a sandbox](https://virtx.sh/docs/guides/setting-sandboxes/#remove-a-sandbox) |

So:

- A package every run needs goes in the image, not in a step the agent repeats.
- The files you hand the agent or want back go on a volume.

The examples in `examples/` all work this way: they build their image once, put their skill and inputs on named volumes, and copy the results back at the end.

### Building an image from a shell

The `virtx` command builds the same images from a Dockerfile, with `docker`'s spelling. The virtx packages install it: `pip install ailoy-py` puts it in the environment's `bin/`, and `@brekkylab/virtx` in `node_modules/.bin`. Without either, run it with `uvx virtx` or `npx @brekkylab/virtx`.

```sh
virtx build -t plot:latest .    # from ./Dockerfile
virtx images                    # the images on the server
```

A sandbox then boots from `plot:latest`. virtx's [Images](https://virtx.sh/docs/guides/images/) covers the rest of the command.

## Inputs and results

- Before a turn, write what the agent should read onto a volume mounted in its sandbox, read-only if it should not change it.
- After the turn, read what it wrote, from the volume or from the sandbox, before the agent closes.
- Say where in the instruction, so the agent knows where to look and where to write.

virtx's [Reading and writing files](https://virtx.sh/docs/guides/reading-writing-files/) covers doing this from your code.

## Picking up later

An agent's work is in two places: its history, and its sandbox's files. To carry on where a run stopped:

- Make an agent with the same history (`from_spec`'s `history`).
- Its sandbox is a new one, so put what a later run starts from on a volume, and mount the same volume in the new sandbox.

## Sandbox options

`{"create": args}` takes virtx's sandbox args in their JSON form, the image as `{"type": "tag", "tag": "..."}` and these options, among others, with the same snake_case keys in Python and Node.js. Rust sets them on `SandboxCreateArgs`. What each means for an agent:

| Option | For the agent | virtx docs |
| --- | --- | --- |
| `volumes` | Where it reads your files and leaves its results. | [Mounting volumes](https://virtx.sh/docs/guides/mounting-volumes/) |
| `network` | Whether its commands reach the internet. On unless turned off. `web_search` and `web_fetch` run in your program, not the sandbox, so they work either way. | [Networks and ports](https://virtx.sh/docs/guides/networks-ports/) |
| `ports` | A server it starts in the sandbox, reached from outside. | [Networks and ports](https://virtx.sh/docs/guides/networks-ports/) |
| `vcpus`, `memory_mib`, `disk_gib` | Room for heavy commands, and for what it installs or writes outside its volumes. | [Setting up sandboxes](https://virtx.sh/docs/guides/setting-sandboxes/) |
| `gpu`, `gpu_memory_mib` | A GPU through Vulkan, for work such as deep learning. | [Using GPUs](https://virtx.sh/docs/guides/using-gpus/) |
| `abins` (`.abin(name)` in Rust) | virtx's own programs at `/abin`, such as `index`, `docread` and `display`. Each one with a `SKILL.md` becomes one of the agent's [skills](/docs/guides/skills/). | [Setting up sandboxes](https://virtx.sh/docs/guides/setting-sandboxes/) |

virtx's [Hello world](https://virtx.sh/docs/hello-world/) covers which server to run, on your machine or elsewhere.

## Troubleshooting

virtx's errors carry a `source` (`server`, `job`, `transport` or `client`) and, from the server, an HTTP `status`. Tell them apart by those, not by the message ([Errors](https://virtx.sh/docs/reference/api/#errors)). A sandbox virtx refuses to make fails `from_spec` with the same status, and a message that starts with `virtx:`.

| What you see | Why, and what to do |
| --- | --- |
| `` `<command>` exited with <code> `` from `build_image(...).complete()` | A step of the recipe failed. The job's log, printed above it by step (`STEP 1/2: …`), shows the command's output. |
| `<image>: not found, or private and pulled without credentials` | The image name is wrong, or the image is private. |
| `no image here is tagged <tag>: pull it first` (status `404`) | Pull or build the image before making an agent whose sandbox boots it. |
| `this server has no virtx to make a sandbox on` (status `422`) | Give Ailoy a virtx client with `set_virtx` before making an agent with a sandbox. |
| `the spec uses a sandbox, and none is given`, or `a sandbox is given, and the spec uses none` (status `422`) | Give `from_spec` a `sandbox` exactly when the spec sets `use_sandbox`. |
| `status` `400`, such as `abins: this server has no program called …` | An option is out of range or unknown. The message names it. |
| `status` `409` | The name is taken, the volume is in use, or the sandbox's VM has exited. |
| `this server was built without a GPU` (status `422`) | This server can't give a GPU. Use a release build of virtx's server. |
| Vulkan in a GPU sandbox finds no device | The host has no Vulkan driver. Install the GPU maker's driver on Linux or Windows; on macOS, virtx brings its own. |
| A command in the sandbox can't resolve or reach a host | The sandbox was made with `network` off, which leaves it no network device. Turn it on, or fetch the data in your program and write it in. `web_search` and `web_fetch` work either way. |
| The agent's file isn't in `/artifacts` | The agent wrote it somewhere else. Name the folder in the instruction, as the examples do, and check the agent's last message for the path it used. |
| The first sandbox fails to boot, with `boot_failed` | See [Installation](/docs/guides/installation/#troubleshooting). |
