An agent is an object in your program. It sends messages to a model (the arrow up). When the model asks for a tool, the agent runs it: sandbox tools run in the [sandbox](#the-sandbox), a microVM with its own Linux kernel (the arrow down), and other tools run in your program. In the drawing, the sandbox mounts folders for the agent's inputs, skills and results (`/models`, `/skills` and `/artifacts`). Files the agent leaves in `/artifacts` reach your disk when your code copies them out.

## What an agent is made of

| Part | What it is | Required | Set with |
| --- | --- | --- | --- |
| Model | The language model that decides what to do, named `<org>/<name>` | Yes | `AgentBuilder("anthropic/claude-haiku-5-5")` |
| Instruction | The system prompt: the agent's role and where to find inputs and leave results | No | `.instruction(...)` |
| Tools | Functions the model can call | No | `.tool(...)`, `.tools(...)`, `.web_search_tool()`, `.browser()`, ... |
| Sandbox | A Linux microVM where the agent's shell and file tools run | No | `.sandbox(sandbox)` |
| Skills | Folders of instructions for one kind of task | No, needs a sandbox | `.skill(dir)` |
| Memory | Notes about the user that last between sessions | No | `.memory(dir)` |
| History | Every message so far | Starts empty | `.history(messages)` |

[Define an agent](/docs/guides/agents/) shows each of these in code.

## What happens in a turn

A turn is one query from you and everything the agent does to answer it:

1. Your query is added to the agent's history.
2. The model receives the history and the descriptions of the agent's tools, and writes a message.
3. If the message is an answer, the turn ends.
4. If the message asks for tools, all the calls run at the same time. Sandbox tools run in the sandbox; the rest run in your program.
5. Each call returns one result, even when it fails, so the model can see what went wrong and try something else. The results are added to the history, and the agent goes back to step 2.

Every message is returned to your code as it completes, and stays in the history. The next query continues the same conversation. [Run an agent](/docs/guides/running/) shows how to read these messages, stream them, and handle errors.

## The sandbox

The sandbox is a Linux microVM created by [virtx](https://virtx.sh/docs/), an open-source runtime built alongside Ailoy. Your code creates the sandbox with the virtx package and passes it to the agent. The agent then gets a shell and file tools that run inside it, so it can install software, write and run code, and keep files without touching your machine.

Files in a sandbox come from two places:

- **The image.** Every sandbox created from an image starts with its files and packages. Put packages that every run needs in the image.
- **Volumes.** A volume is storage on the virtx server that you mount into the sandbox as a folder. Use volumes for inputs, skills and results. A volume outlasts the sandbox, and your code can read and write it while the agent works.

Anything else the agent writes, such as a package it installs, lasts until the sandbox is removed. A sandbox can also use the host's GPU through Vulkan ([Using GPUs](https://virtx.sh/docs/guides/using-gpus/)).

The sandbox belongs to your code, not to the agent. The agent never starts, stops or removes it. Your code creates it, can read and write its files at any time, and removes it when it's done. A sandbox can outlive the agent, so another agent can continue the work.

## Where each part runs

| Part | Where it runs |
| --- | --- |
| The model | The provider's servers, reached through its CLI or API on your machine, or a model server you run yourself |
| The sandbox | A virtx server: your machine when you call `Client.spawn()`, or a remote one |
| Your own functions, `web_search`, `web_fetch` | Your program |
| MCP servers | A stdio server runs as a process on your machine; an HTTP server runs wherever it is hosted |
| The browser | Your machine: your own browser or one the agent starts, controlled from your program |

## Spec and state

Ailoy splits an agent into two parts:

- **Spec**: the model, instruction, tools, skills, memory and model options. A spec is plain JSON, so you can save it and build the same agent again later.
- **State**: the history and the sandbox. This is what the agent has done, and where.

`AgentBuilder` sets both. To rebuild an agent from a saved spec, see [Build an agent from a spec](/docs/guides/agents/#build-an-agent-from-a-spec).
