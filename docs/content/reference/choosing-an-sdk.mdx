The Ailoy SDK comes in three languages. The Python and Node.js packages wrap the Rust crate, so an agent runs the same loop, with the same models and tools, whichever you pick. Choose the language of the program your agent lives in.

## Compare the SDKs

| | Python | Node.js | Rust |
| --- | --- | --- | --- |
| Package | `ailoy-py` on PyPI | `@brekkylab/ailoy` on npm | `ailoy` on crates.io |
| Install | `pip install ailoy-py` | `npm install @brekkylab/ailoy` | `cargo add ailoy` |
| Needs | Python 3.10 or later | Node.js 18 or later | Tokio |
| Waiting | `await`, on asyncio | `await`, on promises | `.await`, on Tokio |
| A turn | `async for` over an `AgentRun` | `for await` over an `AgentRun` | a `Stream` of results |
| Messages | dicts, typed in `ailoy.types` | plain objects, with TypeScript types | Rust types (`Message`, `Part`) |
| Names | `snake_case` | `camelCase` | `snake_case` |
| Reference | [Python](/docs/reference/python/) | [Node.js](/docs/reference/nodejs/) | [docs.rs](https://docs.rs/ailoy/0.3.2/ailoy/) |

## Which one to pick

- **Python** if your agent sits in a Python service or script, or next to data and ML code. It's the shortest way to try an idea.
- **Node.js** if your agent sits in a JavaScript or TypeScript server, a CLI or a desktop app. The package ships its own TypeScript types.
- **Rust** if your program is in Rust, or you want the pieces the bindings don't expose: the model and tool traits to implement your own, a console shared between agents, and the browser's own builder.

```py
import asyncio

from ailoy import AgentBuilder


async def main() -> None:
    agent = await (
        AgentBuilder("anthropic/claude-sonnet-5-5")
        .instruction("Answer in one short paragraph.")
        .web_fetch_tool()
        .build()
    )
    async with agent:
        async for out in agent.run("What is on https://example.com?"):
            for part in out["message"]["contents"]:
                if part["type"] == "text":
                    print(part["text"])


asyncio.run(main())
```

<TabItem label="Node.js" icon="seti:javascript">

```js
const { AgentBuilder } = require('@brekkylab/ailoy')

async function main() {
  const agent = await new AgentBuilder('anthropic/claude-sonnet-5-5')
    .instruction('Answer in one short paragraph.')
    .webFetchTool()
    .build()

  for await (const out of agent.run('What is on https://example.com?')) {
    for (const part of out.message.contents) {
      if (part.type === 'text') console.log(part.text)
    }
  }
  await agent.close()
}

main()
```

#[tokio::main]
async fn main() -> anyhow::Result<()> {

        .web_fetch_tool()
        .build()
        .await?;
    // agent.run(query) is a stream of each message the model and the tools produce
    Ok(())
}

## Moving between Python and Node.js

The two bindings have the same classes, functions and parameters. Only the spelling differs:

- Methods and functions are `snake_case` in Python and `camelCase` in Node.js: `run_stream` is `runStream`, `set_lang_model_provider` is `setLangModelProvider`.
- Message, output and spec keys are the same in both, in their JSON form: `finish_reason`, `tool_calls`, `model_options`.
- Where Python takes keyword arguments, Node.js takes one options object: `AgentBuilder.browser()`, `AgentBuilder.context_manager()` and `Agent.from_spec()`.
- Python raises `AiloyError`. Node.js throws an `Error` whose `code` is `AILOY_ERROR`. See [Errors](/docs/reference/python/errors/).
